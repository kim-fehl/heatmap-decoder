# M8 — Colourbars, label regions and count proposals

M8 adds review-only proposals and hybrid manual inputs to M7. It introduces no
automatic hand-off, count acceptance gate, tick-value OCR, rotated text, GUI or
scientific identifier correction. Numerical endpoints remain user-owned, and
values still describe the figure's plotted scale.

## Input and review contracts

Existing M7 hints continue to work. Each axis must have a positive supplied count
or an explicit `infer_rows: true` / `infer_columns: true`. Inference may also be
requested alongside a supplied count to show disagreements; the supplied count
remains authoritative. Missing legacy fields never implicitly enable inference.

`requested` accepts `heatmap`, `colourbar`, `labels_rows`, `labels_columns`. Fixed
heatmap/colourbar coordinates and fixed label sources conflict with requests to
detect the same region and are rejected. Label-only requests need no bar. Label
search requires a fixed/reviewed heatmap. Without one, detection retains other
proposals and tells the user to review the heatmap first. Count hypotheses are
associated with each shortlisted heatmap box; they never adjust a box in a loop.
When a count is unknown, ROI ranking uses occupancy/variation only and explicitly
marks grid scoring unavailable, without inventing counts or grid evidence.

For example, the bundled upright labelled figure uses:

```json
{
  "rows": 4,
  "columns": 3,
  "heatmap_bbox": [220, 140, 1000, 460],
  "requested": ["colourbar", "labels_rows", "labels_columns"],
  "colourbar_start_value": 2,
  "colourbar_end_value": -2
}
```

An explicit count-only request on the supplied grid is:

```json
{
  "heatmap_bbox": [25, 25, 185, 145],
  "requested": [],
  "infer_rows": true,
  "infer_columns": true
}
```

Unknown fields, nonintegral counts, invalid regions and conflicting inputs fail
clearly. Detector settings extend M7 with `max_count` (128),
`max_count_candidates` (8 per axis per box), `label_search_pixels` (256),
`label_padding_pixels` (4) and `max_ocr_pixels` (4,000,000 per resized search crop).
Bounds and validation limits are defined in `DetectorOptions`.

Detection still writes `roi_candidates.json`, `roi_diagnostic.png` and
`config_proposed.json`, exiting **5** for all proposed/unresolved geometry/counts.
ROI JSON schema **2** records associations, count signals/pitch/phase/conflicts,
manual selections and raw OCR localisation evidence. M7 schema 1 remains readable.
ROI statuses remain separate from label statuses. Missing requested labels are
listed in incomplete-config metadata; proposals never populate label sources or
counts by rank. Proposed config contains supplied fields only. Endpoints are never
invented. The overlay identifies each region kind, marks ambiguity and draws the
first count hypothesis per axis/box with an explicit question mark; alternatives
remain in JSON, and drawing a grid does not select its count.

Review by editing ordinary extraction fields, or by supplying a separate JSON:

```json
{
  "regions": {
    "colourbar": "colourbar-001",
    "labels_rows": "labels_rows-left",
    "labels_columns": "labels_columns-above"
  },
  "counts": {}
}
```

`extract --roi-review roi_candidates.json --roi-selections selections.json` applies
those explicit IDs. An optional count selection maps `rows`/`columns` to IDs such
as `count-heatmap-manual-rows-6`. A reviewed bar can supply its physical orientation;
start/end values still mean top/bottom or left/right and must be entered manually.
The M7 `--heatmap-candidate` shorthand remains supported. Conflicting shorthand
and JSON selections, wrong kinds/IDs, image hash/dimension mismatch, incompatible
count/box hypotheses, inconsistent pitch/phase and fixed-input changes fail before
matrix export. Requested labels cannot silently become numeric-only extraction
when importing saved review. Explicit file/manual label sources remain available.

Extraction provenance keeps detection evidence, configuration/ROI/selection-file
hashes, selected region/count origins and raw numerical/OCR QC. Selecting a text
region does not accept its text; the existing OCR label gates and optional
`--labels-review` workflow run unchanged. An edited complete ordinary config needs
no detector rerun. Include `--roi-review` to validate and preserve evidence; without
it extraction treats the config as a deliberate ordinary manual invocation.
Always resolve all requested sources first. Existing output/input protection and
`--overwrite` policy remain intact.

## Methods and deliberate limits

**Colourbars:** bounded connected-component proposals include horizontal/vertical
elongated strips. A bounded collinear join can bridge neutral palette gaps only
when short-axis extents agree. Original-resolution refinement removes thin uniform
border strokes without extending the observed scale. Bar eligibility requires
aspect >=4, length >=24 px, thickness >=2 px, low transverse variation, sufficient
long-axis variation, >=97% small adjacent steps (<=12 RGB-channel units) and >=20%
changing steps. Discrete annotation strips fail continuity/change checks in the
fixtures. Partial alternatives remain reviewable, with scale completeness marked
unverified; bars touching an image edge carry a possible-clipping reason. No bar
proposal identifies the numerical limits by itself.

Associations retain separate CIELAB palette coverage, axis overlap and proximity
scores. A proposal must pass all three constraints; proximity or similar palettes
alone is insufficient. The result lists competing/shared associations and never
chooses one. The bar detector does not import or probe OCR unless labels are
explicitly requested. Low-resolution/quantised palettes, thick/nonuniform borders,
compression and blur can cause abstention; these failures are reported below.

**Labels:** sparse text (`--oem 1 --psm 11`) is searched in bounded left/right and
above/below strips. The existing local OCR adapter and deterministic grayscale /
upscaling / coordinate transforms are reused. Raw engine versions, tokens and
original-coordinate boxes are retained. Complete-link grouping before slot
assignment supplies unassigned geometric observations for count support. Ordinary
label assignment then uses the unchanged v0.2 slot rules and thresholds. Regions
need at least two aligned slots, or the only supplied slot; partial regions carry
incomplete/ambiguity/low-confidence reasons. Slot count/order and unresolved text
are preserved. Competing sides remain ambiguous. Crops exceeding the pixel cap,
missing engines/language data and OCR failures yield saved unresolved artefacts
with actionable warnings. No threshold search or relaxed label acceptance occurs.

If the requested axis count is unknown, raw OCR positions are retained for count
hypotheses, but label-region localisation waits for count review. Upright token
geometry cannot establish biological identity or reliably distinguish perfectly
aligned captions/ticks from labels: text identity remains explicitly unverified.
Internal geometry may use a placeholder for an *unused* axis when assigning a
known axis; no placeholder count is exported or used for numerical extraction.

**Counts:** full-resolution transition positions are aggregated across bounded,
spatially distributed cross-axis samples. Thin uniform strokes with contrasting
neighbours supply a separate named observation. Explicit label searches can add
unassigned group centres; assigned labels are never counted as independent
support. Candidate integers are bounded by `max_count` and a minimum 3-pixel pitch.
Each is fitted to the supplied box's outer lattice, recording boundary/centre
alignment, coverage, pitch, phase, conflicts and harmonic alternatives. Missing
observations lower coverage rather than compressing the grid. Disagreeing signals
remain in each proposal. Signals from the same underlying image profile are not
claimed to satisfy M9's independent-support gate. Completeness and harmonics remain
unverified, and every inferred count stays unresolved until explicitly reviewed.
Uniform/weak axes abstain. Some adjacent equal colours make the true count
fundamentally unidentifiable without additional information.

## Runnable examples and actual finite evidence

From the repository root with local Tesseract and the OCR extra installed:

```bash
uv run --extra ocr heatmap-decoder detect examples/labels/reconstruction.png --config examples/roi_m8/hints.json --out work/m8-roi
# Expected exit 5; inspect the overlay and IDs before using the fixed example review.
uv run --extra ocr heatmap-decoder extract examples/labels/reconstruction.png --config work/m8-roi/config_proposed.json --roi-review work/m8-roi/roi_candidates.json --roi-selections examples/roi_m8/selections.json --out work/m8-results
uv run heatmap-decoder detect examples/roi_m8/count_complete.png --config examples/roi_m8/count_hints.json --out work/m8-counts
# Expected exit 5; no counts are filled into config_proposed.json.
```

The complete fixed reviewed example verifies output order and compares against
manual numerical extraction:

```bash
uv run --extra ocr python examples/roi_m8/workflow.py --out work/m8-example
uv run python examples/roi_m8/generate.py
uv run --extra ocr python examples/roi_m8/benchmark.py --ocr
```

The example uses the original M6 fixed upright image; no new font is needed at
runtime. Detector `m8.1` yields exact 7/7 labels, zero unresolved slots after review
and identical displayed-scale numbers. The OCR CI job now runs this workflow too.
All new synthetic figures/code are original MIT material. Base layouts/splits are
predeclared before evaluation, with transformations kept in the same split. This
small regression split is not an independent practical benchmark or an M9 gate.

`examples/roi_m8/benchmark.json` retains all 25 records, including failures (count
axes are separate records). Across eight count-axis attempts: candidate recall
6/8, proposal coverage 6/8, abstention 2/8, rank-one exact count 4/8 (4/6 among
covered cases), off-by-one errors 0/6 and integer-multiple errors 2/6. These are
ranking diagnostics, not accepted count accuracy. Automatic ROI/count acceptance
coverage is zero, correct-acceptance rate undefined, and automatic false acceptance
zero by policy. Zero acceptance is not evidence of validated useful automation.
Mocked tests additionally cover missing labels supporting a 6-slot lattice from
five observed strings, misleading spanning captions, low-confidence text, both
opposite sides, competing sides, unavailable OCR, contradictory inputs and invalid
saved evidence. Local OCR environment: Tesseract 5.5.0, pytesseract 0.3.13, English;
CI uses its recorded Ubuntu engine/language environment.

No independently annotated real-figure set or useful automatic acceptance claim is
included. Touching annotations/dendrograms, low contrast, very small/partial grids,
unknown text orientation, shared scales, strongly degraded bars and nonopaque
images may need manual inputs. M7 regression tests and existing numerical/OCR
behaviour remain covered; M9 validation and automatic acceptance are future work.

Validation: 218 tests passed with OCR enabled, plus 18 subtests. Ruff and mypy
passed, as did source/wheel builds, installed-wheel smoke checks and the documented
reviewed M8 workflow. Checks ran locally; cross-platform/OCR CI runs on push.
