# M12 — Selective automation and practical validation

M12 implements a composable runtime classifier, realistic scale/string tests,
and a new preregistered synthetic corpus. Release eligibility is measured separately
from experimental runtime acceptance. Automatic publication remains under review;
no policy boolean was changed to bypass evidence.

## Implemented behaviour

`AutomationRequest`/`automate` and the `automate --request` CLI share the deployed
classifier. They evaluate geometry, heatmap/bar association, supplied or requested
counts, manual/reviewed or recognised linear scale, identifier review and numerical
quality. Partial successes remain visible when a required capability abstains.
The CLI writes JSON, labelled ROI diagnostics and available tick-review artifacts,
then exits 5 before any new matrix files. Existing matrix files are preserved.

Supplied counts plus accepted regions plus reviewed tick anchors compose. Inferred
counts retain observation provenance, conflicts and harmonic alternatives, but
abstain because outer completeness and uniqueness are not established. Fully
requested automatic attempts receive no truth boxes, counts or endpoints.

Horizontal tick words are grouped inside bands determined by measured stroke
midpoints, preventing nearby numeric labels being merged into one line. Tokens
crossing bands remain intact; no fit-compatible outliers are removed. Numeric
parsing still refuses guessed minus signs, O/0 substitutions and units.

Known-grid label sources optionally use `recognition: "slots"`: bounded single-line
OCR per axis slot, retaining every crop and raw engine run. This preserves the
existing sparse mode and assignment/review semantics. OCR confidence does not
verify biology; neither strategy restores missing underscores or aliases genes.

## Frozen corpus and evaluation

[Preregistration](benchmarks/m12/preregister.json) and
[corpus hashes](benchmarks/m12/corpus.sha256) were written before OCR tuning.
The Pillow renderer, independent of recognition code, uses 75 distinct seeded matrices: 15 development,
15 validation and 45 untouched test bases. Clean/blur/JPEG derivatives remain with
their base, yielding 225 ordinary images. Templates, font and gene list are shared
across splits; new matrix seeds do not establish unseen-source generalisation. All ordinary cases remain eligible for
the denominator regardless of detector success. There are 10 negative/challenge
bases per split, with [mode applicability](benchmarks/m12/challenge_scope.json)
fixed before end-to-end evaluation.

Three layout families cover flank vertical bars, cap horizontal bars and cross-axis
bars, with both orientations across all four sides. Each has 20–30 genes and 6–10
samples, left/right gene text, top/bottom sample text, 3/5/7 ticks, both colour
directions, grid/no-grid and clean, sigma-0.65 blur or quality-85 JPEG rendering.
Ranges include **−4…4, −3…3, −2…2, −4…2 and −3…4**. Synthetic scores are clipped
displayed quantities; these are not original expression counts or publication images.

Truth geometry, dimensions, tick strings/values/positions and identities come from
the renderer independently of recognition. Each deployed decision precedes truth
scoring. Scoring only measures the runtime-selected candidates, never an oracle
choice from the top three. The [policy freeze](benchmarks/m12/policy-freeze.sha256)
precedes validation/test execution; no tuning follows test inspection. The
selective pipeline is `m12-selective.1`, ROI checks are `m10-development.1`, and
stroke-band legend checks are `m12-linear-review.1`. The early development report
retains the preceding legend version label; the implementation was unchanged
apart from that label before the validation/test freeze.

A separate [renderer audit](benchmarks/m12/renderer-audit.json) found overlapping
numeric tick boxes in 2/45 test bases and tick/identifier overlaps in 7/45; each
smaller split had 2/15 tick/identifier overlaps. These violate the intended
separated-text envelope. They remain in the original denominator, with no
post-hoc exclusions. Together with the synthetic-only scope, this limits what
this corpus establishes about ordinary published heatmaps. Correcting the corpus
requires a fresh preregistered hold-out rather than relabelling failed cases.

Four modes are evaluated independently: supplied dimensions/scale with automatic
ROIs; inferred dimensions with supplied scale; supplied dimensions with OCR scale;
and fully requested geometry/counts/scale. Tests use no annotated ROI injection.
A missing scale tick is a challenge for OCR-scale modes; manual supplied scale
workflows do not depend on tick visibility. Wrong supplied hints apply to modes
that request supplied counts.

Required gates include ≥30 accepted distinct bases across ≥3 families, ≥70% complete
ordinary coverage, zero observed wrong complete/challenge acceptances, edges within
0.1 true pitch/1px, MAE <2% of true range, maximum error ≤5%, full finite coverage
and ≤1% cell flags. Inferred axes additionally require ≥10 exact accepted bases each
across ≥3 families. Zero observed errors are not a population guarantee; the report
includes a one-sided 95% binomial upper bound using distinct accepted bases, with
shared-renderer dependence explicitly limiting its interpretation.

## Results

Final development, validation and test summaries are recorded alongside all failed
attempts in `benchmarks/m12/`. Development and validation each accepted 4/45 ordinary attempts (8.9%) in the
supplied-count/supplied-scale ROI mode and 3/45 (6.7%) with supplied counts/OCR
scale. Both inferred-count modes accepted 0/45. Accepted cases covered only two
ROI families, and the competing-bar challenge was experimentally accepted once
in each split. All four release gates failed. Held-out results follow below.

Conditional development string measurements are separate from release coverage.
Before stroke-band grouping, 196/225 expected tick values were recovered exactly;
afterwards, 198/225 (87.1% → 88.0%). Development-eligible scales stayed at 22/45.
This modest improvement does not establish general OCR reliability.

For 9 known-grid development images (three base sizes and clean/blur/JPEG), gene
strings were 224/225 exact with either strategy. Sample strings were 52/72 exact
with sparse OCR and 49/72 with slot OCR. The engine nevertheless accepted 1 wrong
sparse and 4 wrong slot sample strings at the configured confidence threshold.
This is why slot OCR is optional, sparse remains the default, and automation
requires identifier review. [Full identifier evidence](benchmarks/m12/identifiers-development.json)
includes the raw strings and confidence values; no biological verification claim
follows from these measurements.

The README's bundled 20×6 development example has experimental complete acceptance
with an automatic horizontal bar and recognised −4…4 scale. It still exits for
review because corpus-level release gates apply independently of one example.
Its actual region/text evidence and image are reproducible with
`examples/m12/recognition.py`.

## Held-out release decision

The [untouched test report](benchmarks/m12/test.json) contains **580 requests**:
135 ordinary images plus 10 challenge images, each attempted in four modes.
[Supplemental metrics](benchmarks/m12/test-metrics.json) and the
[computed release decision](benchmarks/m12/release-decision.json) preserve the
original runtime choices.

| Mode | Ordinary complete accepted | Coverage | Distinct bases / families | Challenge accepted |
| --- | ---: | ---: | ---: | ---: |
| Supplied counts and scale; automatic ROIs | 11/135 | 8.1% | 11 / 2 | 1/6 |
| Inferred counts; supplied scale | 0/135 | 0% | 0 / 0 | 0/5 |
| Supplied counts; OCR scale | 8/135 | 5.9% | 8 / 2 | 0/10 |
| Fully requested automatic pipeline | 0/135 | 0% | 0 / 0 | 0/9 |

**All four release gates failed; automatic exports remain disabled.** Counts
have zero exact accepted inferred examples per axis. Neither ROI mode reaches
30 accepted bases, three families or 70% coverage. The competing-bar challenge
was experimentally accepted in the supplied-scale ROI mode. This is an observed
failure, retained in evidence; it was not patched after inspecting test results.
No wrong ordinary complete layout/count/scale was accepted. Each base contributed
at most one accepted derivative; all complete ordinary acceptances were clean
images. Blur/JPEG abstentions remain in the denominator.

Among accepted ordinary tables, worst MAE was **0.1128%** of true range with
supplied scale and **0.1163%** with OCR scale; maximum cell errors were **0.4488%**
and **0.4749%** respectively. All values were finite and no cells were flagged.
Accepted geometry met the annotated edge limits. Low reconstruction errors on
this selected subset do not compensate for low coverage or the challenge error.
With only 11/8 accepted distinct bases, zero-error 95% upper bounds are about
23.8%/31.2%, subject to shared-renderer dependence; this is weak reliability evidence.

For each OCR-scale mode, 675 ticks were expected across ordinary inputs, but only
67 plausible records were produced after runtime bar acceptance; 51 were correctly
associated and 45 had exact values. Eight scale-capability acceptances had complete
exact tick sets, endpoint span 1.0 and maximum position residual 0.5715px. Those
eight scale successes remain visible in fully automatic mode despite count
abstention. One observed sign error occurred in an **unresolved** scale
(`test-28-clean`), and was not accepted. Counts of exact values include unaccepted
suggestions; missing bars/ticks remain in the full expected denominator.

Median wall times were 0.78s/3.33s/0.81s/3.44s for modes 1–4; maxima were
2.22s/10.69s/6.32s/14.22s. Concurrent execution and the CPU quota limit their use as
latency estimates. Test choices and policy/corpus hashes were frozen before this
analysis; later improvements require new independent validation evidence.

## Verification

- 436 tests and 18 subtests pass, including real Tesseract integration and 45
  realistic range/direction/anchor cases. An initial property-test timing deadline
  failed under heavy benchmark contention; isolated and full reruns passed.
- Ruff and strict mypy pass. Existing numerical, v0.2 label review, M8 ROI review,
  M9 abstention and reviewed M11 workflows pass; the M12 workflow confirms
  diagnostic artifacts and no matrix publication.
- M9's 45 frozen files match the pre-M10 commit. M10/M11 historical report/script
  hashes remain unchanged; corpus and frozen policy hashes verify.
- Installed-wheel and source-distribution smoke checks verify the new API,
  diagnostics, packaged examples/docs/evidence and operation without OCR.

## Reproduction and limits

```bash
uv sync --locked --extra ocr
# Renderer requires DejaVuSans; install fonts-dejavu-core if absent.
uv run --extra ocr python benchmarks/m12/evaluate.py \
  --split validation --out work/m12-validation.json
uv run --extra ocr python benchmarks/m12/evaluate.py \
  --split test --out work/m12-test.json
uv run --extra ocr python examples/m12/workflow.py --out work/m12-example
HEATMAP_DECODER_OCR_TESTS=1 uv run --extra ocr pytest -q
uv run ruff check .
uv run mypy src
uv build
uv run python tests/smoke_distribution.py
```

Evaluation refuses to overwrite an existing report. Re-running an inspected test
set is regression evidence, not a fresh hold-out. Historical M9/M10/M11 benchmark
files remain unchanged. Detailed overrides, request schemas and review steps live
in [automation docs](docs/automation.md), [usage](docs/usage.md) and
[scale review](docs/legend.md).

[Environment metadata](benchmarks/m12/environment.json) records Python, OCR engine,
English data hash and font. Wall times include concurrent jobs in this environment
and are not isolated latency measurements. No licensed publication figures were
added; evidence remains synthetic-only and does not validate diverse real figures.
Row transformations cannot be inverted to recover expression counts. Endpoint
matches indicate possible clipping bounds; blur/interpolation may destroy colour
information. Residuals and colour errors are engineering diagnostics, not calibrated
uncertainty intervals. Every biological identifier remains subject to human review.
