# M5 — local OCR and review artifacts

The optional adapter uses local Tesseract via `pytesseract`, imported only when
OCR is requested. Numeric extraction, geometry tests and text-file label sources
do not import or check the wrapper/engine. No cloud OCR, OpenCV, automatic layout
detection, rotation, dictionary correction or biological identifier lookup is used.

## Installation and example

Install the wrapper with `uv sync --locked --extra ocr`, or install this checkout
with `python -m pip install -e '.[ocr]'`. For an installed distribution use
`python -m pip install 'heatmap-decoder[ocr]'`. The engine is a separate install:

- Debian/Ubuntu: `sudo apt-get install tesseract-ocr tesseract-ocr-eng`.
- macOS: `brew install tesseract`.
- Windows: install Tesseract and its English traineddata, then add its executable
  directory to PATH. Check `tesseract --version` and `tesseract --list-langs`.

```bash
uv run --extra ocr heatmap-decoder labels examples/labels/clean.png \
  --config examples/labels/config.json --out review/
```

The command needs only `heatmap_bbox`, `rows`, `columns`, and `labels`; it also
accepts a complete valid numeric extraction configuration. Bounds are original
image pixels with right/bottom exclusive. Row labels are genes, column labels
samples, in displayed order. Text must be horizontal, upright and single-line.
ROIs may be on either side of the heatmap. Labels are not transposed or sorted.
The configured ROI must include complete text with enough padding; column words
must fit within their column's full band. Unsupported or overlapping layouts
remain unresolved. No automatic region discovery or heuristic word splitting.

Omit either axis to use generated positional slots for that axis. An alternative
to OCR is `{"source": "file", "path": "genes.txt"}`: one non-empty UTF-8 string
per row/column, with exact counts. Relative paths resolve beside the config file.
Only outer whitespace is trimmed. Duplicate text is preserved and flagged.
Text-file sources require neither pytesseract nor Tesseract.

## Fixed OCR and confidence rules

Preprocessing crops the validated region, converts to Pillow `L` grayscale, and
upscales with bicubic interpolation (default factor 3). One Tesseract pass uses
`--oem 1 --psm 11`: LSTM sparse upright text, without orientation detection.
No variants are searched or chosen based on plausible text. Each call has a
30-second timeout. The existing four OCR settings are the entire public tuning
surface: `language`, `upscale_factor`, `min_confidence`, and
`max_axis_offset_fraction`. Defaults remain `eng`, 3, 80 and 0.4.

Candidate confidence is the minimum valid token confidence. Confidence -1 and
empty structural records are retained as evidence but do not become candidates.
Grouping and fixed-slot assignment use the M4 geometry implementation; no case,
punctuation, digits or ambiguous characters are corrected. Confidence is an
engine heuristic, not a probability, validated biological guarantee, or numerical
colour-matching diagnostic. Verify even accepted labels against the figure.

## Artifacts and exit codes

`labels` writes only four review artifacts:

- `labels.tsv`: every row and column slot, including omitted/generated axes,
  with `axis`, `index`, `raw_text`, `final_text`, `confidence`, `bbox`, `source`,
  `status`, `duplicate`, `issues`. Proper TSV quoting preserves embedded tabs,
  quotes and collision evidence containing newlines. Unavailable fields are empty.
- `labels_review.tsv`: exactly `axis`, `index`, `text`, for requested axes only.
  Accepted/file labels are prefilled; unresolved strings are empty. All entries
  are editable. Review import will be implemented in M6.
- `labels_diagnostic.png`: configured ROIs, expected centres, raw token and
  candidate boxes, and a ledger showing every slot index/status. Missing slots,
  ambiguous candidates, duplicates and unmatched candidates remain visible.
- `provenance.json`: source hash/config, observed engine and wrapper versions,
  language availability, fixed mode and preprocessing, raw resized-crop tokens,
  original-coordinate text tokens/candidates and assignments, and file-label
  hashes when applicable. Structural records retain their raw coordinates.

Exit **0** means requested slots are resolved, **4** means review files were
written with unresolved slots, and **2** means invalid input, unavailable OCR or
an I/O error. Unmatched candidates and duplicates also emit warnings. These
statuses assess engineering completeness, not correctness or biological identity.
Review artifacts require explicit `--overwrite` to replace existing files.
Input figure/config/label files are protected even with that flag.

The command never publishes `matrix.csv` or `quality.csv`. Numeric `extract`
continues to reject label-bearing configurations explicitly until M6. For a
numeric-only invocation use the existing numeric config without label sources.
M6 will connect the same label implementation to reviewed, gated reconstruction.

## Fixed fixtures and measurements

`examples/labels/` contains checked-in clean, blurred, JPEG and deliberately
unreadable fixtures, their grid/ROI config, exact truth, and generator metadata.
The generator uses DejaVu Sans 30 px (fonts-dejavu-core 2.37-8 locally), four
gene symbols and three sample strings, including mixed case, digits, a hyphen,
underscore, and an internal space. Integration tests read the fixed images;
they never regenerate them or tune confidence thresholds to make them pass.
Blur radius is 2, JPEG quality 35/subsampling 2, and unreadable blur radius 12.

Local measurements used Python 3.12, Pillow 12.3.0, pytesseract 0.3.13,
Tesseract 5.5.0 (`5.5.0-1+b1`), and Debian English data `1:4.1.0-2`.
English traineddata SHA-256:
`7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2`.

| Fixture | Exact accepted labels | Raw exact labels | Unresolved slots |
| --- | --- | --- | --- |
| Clean | 7/7 (100%) | 7/7 (100%) | 0/7 (0%) |
| Blur | 6/7 (85.7%) | 6/7 (85.7%) | 0/7 (0%) |
| JPEG | 6/7 (85.7%) | 7/7 (100%) | 1/7 (14.3%) |
| Unreadable | 0/7 (0%) | 0/7 (0%) | 7/7 (100%) |

For the blurred fixture, `TP53` became `TPS3` with confidence 91 and was accepted.
This is retained unchanged in the evidence: high confidence can still be wrong.
For JPEG, one exact raw string fell below the confidence threshold and stayed
unresolved. These measurements describe these fixtures and engine/data versions;
they do not promise universal OCR accuracy.

## Validation and CI

```bash
uv sync --locked
uv run pytest -q
uv run ruff check .
uv run mypy src
uv sync --locked --extra ocr
HEATMAP_DECODER_OCR_TESTS=1 uv run --extra ocr pytest -q -s -m ocr_integration
uv build
uv run python tests/smoke_distribution.py
```

Core CI keeps the wrapper absent and skips four opt-in engine-sensitive tests.
Mocked tests cover adapter data/confidence, unavailable wrapper/engine/language,
timeouts, grayscale/scaling, grouping/collisions, TSV quoting, review templates,
provenance, file labels and output/input protection. Numeric regression tests
remain in the same suite. A separate Ubuntu 24.04/Python 3.12 OCR job installs
the distribution's Tesseract and English data, reports versions and traineddata
hash, runs the fixed integration fixtures, and exercises the labels command.
Engine-sensitive CI results must be assessed against the versions it logs;
local 5.5.0 measurements are separate from the CI distribution's engine.

Verified locally: **117 core tests and 18 validation subtests passed with the
optional wrapper uninstalled** (four opt-in tests skipped). With OCR enabled,
**all 121 tests and 18 subtests passed**. Ruff and strict mypy passed, the source
and wheel built, and the installed wheel smoke test passed without OCR extras.
Real separate-process checks confirmed numeric extraction succeeds with Tesseract
absent from PATH, while OCR fails with installation guidance and no new outputs;
the same error behavior was verified with the wrapper uninstalled. The bundled
numeric matrix, quality CSV and diagnostic PNG remain byte-identical to M4 and
the M1–M3 baseline. GitHub CI must separately confirm its recorded engine/platform.

Completed milestones remain M4/M5. Review ingestion, labelled CSV exports,
strict reconstruction publication gating and the completed v0.2 workflow are M6.
