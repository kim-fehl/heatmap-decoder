Implemented from reviewed work commit 505f24e using

M14/M15 have not started. Automatic export and identifier verification policy
remain unchanged.

## Implementation

Column OCR sources accept strict integer text_rotation_degrees 0/90/-90,
defaulting to 0. Rotated rows, other angles, bools, floats and strings are
rejected. File sources do not accept an angle. The sign is the visual
counter-clockwise rotation in the original figure; normalisation applies its
inverse. See [sign diagram and commands](../rotated-labels.md).

CropTransform composes crop origin, an exact Pillow quarter turn and upscale.
Half-open boxes map all four corners; no pixel interpolation occurs at the
rotation step. Existing grayscale/bicubic upscale is preserved. OCR grouping
uses upright geometry while column bands and assignment use original x.
Whole-region reading order cannot reverse final column indices. Slot mode slices
original column bands, normalises each, groups its words and retains run-local
evidence before aggregate assignment. Missing slots, duplicate text and spanning
candidates keep existing review behaviour. Matrix sampling/calibration is unchanged.

Provenance retains raw upright tokens, original tokens/candidates, candidate
boxes in both frames, membership, crop, angle, transform and engine run links.
The existing 128 slot-call, 16-million-pixel and 60-second budgets are preserved.
Whole-region label crops also have a 16-million-upscaled-pixel cap.

## Measured OCR results

[44-attempt report](../../benchmarks/m13/report.json) and
[reproduction instructions](../../benchmarks/m13/README.md).
Every attempt has eight long sample strings. These are conditional synthetic
development trials using explicit ROIs/counts/angles, not real-publication
validation or automatic orientation evidence.

| Cases | Raw exact | Accepted exact | Geometrically assigned | Unresolved | Wrong heuristic accepted |
| --- | ---: | ---: | ---: | ---: | ---: |
| Clean supported, eight runs | 64/64 | 64/64 | 64/64 | 0/64 | 0/64 |
| Underscore/hyphen challenges, 36 runs | 8/288 | 8/288 | 288/288 | 206/288 (71.5%) | 74/288 |

Clean supported runs cover both signs, above/below, and sparse/slots recognition,
with all eight strings in displayed order in each run. They include spaces,
hyphens and mixed case. Challenges include underscores, numeric suffixes,
DejaVu Sans/Serif/Mono, clean images, JPEG quality 85 and blur sigma 0.65.
Raw exact challenge accuracy is 2.8%; wrong heuristic acceptances stay visible.
No spelling correction, underscore reconstruction or confidence threshold tuning
was introduced. Geometric assignment means one candidate within the renderer's
original column band; it does not validate spelling or biological identity.

Environment: Python 3.12.14, Tesseract 5.5.0, pytesseract 0.3.13, Pillow 12.3.0,
NumPy 2.5.4. The report records font hashes and per-attempt runtime.

## Reviewed reconstruction

The [bundled figure](../../examples/m13/figure.png) was visually inspected:
eight +90° names above a 4 × 8 matrix, with no overlapping or clipped text.
It includes the underscore failures. Its reference review TSV was checked
against the displayed synthetic names. Label review changes final names while
preserving raw OCR. Both documented CLI commands completed.

[Reviewed CSV](../../examples/m13/reviewed_matrix.csv) and
[compact evidence](../../examples/m13/reviewed_evidence.json) record all eight
correct column names, values identical to numeric-only decoding, 32/32 finite
cells and zero QC flags. Against plotted synthetic truth, MAE is 0.1012% and
maximum error 0.1961% of the displayed scale range. This is a manual ROI/count/
scale workflow with explicit reference label review, not identifier automation.

## User-requested padding experiment

A subsequent [padding probe](../../benchmarks/m13/padding-report.json) expanded
the original per-column crop by 3, 5 and 8 pixels on each side and separately
added artificial white borders of the same size. On the bundled +90° Sans
underscore fixture, every variant remained 0/8 exact raw strings, identical
to the original crop; expanded-crop assignment remained 8/8. Underscores were
already visible within the crop. Padding did not resolve this recognition
weakness, so production crop defaults and spelling remain unchanged.
