# M7 — Heatmap proposals and coordinate review

Implemented M7 only. M1–M6 were verified at work-branch commit `63b6760`: the
baseline passed 138 ordinary tests (5 OCR integration tests skipped), Ruff and
mypy; with the local OCR extra/engine enabled all 143 tests passed.

## Delivered behaviour

`DetectionHints` requires positive, strictly integral `rows` and `columns`.
`requested` supports only `heatmap` in M7. Unknown fields, inferred counts,
unsupported region kinds and conflicting manual/detection instructions fail.
Manual heatmap and colourbar boxes are validated and preserved. With a manual
heatmap set `requested: []`; this bypasses localisation. A fixed-grid consistency
check may warn about weak evidence, but never moves manual coordinates.

The detector uses background-distance connected components at two bounded
resolutions. RGB variation preserves eligibility of grayscale palettes. Small
morphological closing bridges thin gridlines, with no unrestricted merging of
panels. Exact independent resize ratios round boxes outward. Shortlisted boxes
are refined using original pixels; uniform outer strokes are trimmed at most four
pixels. Scores record occupancy, cell-interior constancy, between-cell variation,
fixed-grid consistency and outer boundary contrast. Scores are engineering
heuristics, separate from colour QC and OCR confidence.

Default settings: maximum analysis side 512 pixels and a second 256-pixel scale;
64 components per scale; 12 exported candidates; closing footprint 3 pixels;
background RGB-channel distance 12; minimum weighted score 0.65. Candidate filtering
also requires variation score >=0.2 and equal-grid score >=0.8. Grid interiors use
3×3 samples, at most 32 slots per axis, evenly distributed across the supplied
grid. Cells below three pixels per axis cannot generate a supported proposal.
Options and detector version `m7.1` are saved. Results are deterministic for the
same image/options/version; IDs belong to the saved result.

All detected boxes require review. Multiple plausible boxes stay ambiguous even
if the export cap hides alternatives. No automatic ROI/count acceptance exists.
No colourbar or label localisation, count inference, rotation, tick OCR or GUI
was added. Existing OCR and numerical extraction remain intact.

## Review and outputs

Run from the repository root:

```bash
uv run heatmap-decoder detect examples/figure.png --config examples/roi/hints.json --out work/m7-roi
# Expected exit 5: localisation is review-only. Inspect the overlay first.
uv run heatmap-decoder extract examples/figure.png --config work/m7-roi/config_proposed.json --roi-review work/m7-roi/roi_candidates.json --heatmap-candidate heatmap-001 --out work/m7-results
```

The example's manual colourbar orientation/endpoints accompany the hints. The
heatmap proposal is the bundled reference's exact `[24, 32, 264, 272]` grid.
Candidate `heatmap-001` is explicitly selected only after inspection.

`roi_candidates.json` includes schema, source hash/dimensions, detector
version/options, candidates, reasons, selected manual regions and unresolved
requirements. `roi_diagnostic.png` overlays numbered proposals, scores, supplied
dimensions and manual selections. `config_proposed.json` contains ordinary
extraction fields, only supplied/resolved boxes and user-owned endpoints. The
metadata names missing required fields; the file is deliberately invalid as a
complete extraction config until those fields are reviewed/supplied. It contains
no fake numeric endpoints or selected-by-rank box.

Alternatively, edit `config_proposed.json` to add reviewed bounds and run ordinary
`extract --config` without detection. To preserve evidence, additionally pass
`--roi-review roi_candidates.json`. Candidate selection through
`--heatmap-candidate` requires `--roi-review`. Import checks the image SHA-256 and
dimensions, schema, duplicate/unknown IDs, all boxes, supplied counts and manual
coordinate conflicts. Extraction provenance retains raw evidence, selection
origins, reviewed config, detection JSON hash and input config hash. Editing alone
without `--roi-review` is an ordinary manual extraction; the software cannot know
that its coordinates came from detection. Relative file-label sources are rebased
to the proposed config location.

Exit 5 means review/unresolved geometry, with all ROI artefacts saved and no
matrix outputs. Exit 2 means invalid hints/input/review or an overwrite error.
Exit 0 means requested geometry was already manually resolved; accompanying
metadata can still report missing extraction fields such as endpoints.
The existing explicit `--overwrite` policy applies to every ROI output.

## Actual finite proposal quality

Reproduce all attempts:

```bash
uv run python examples/roi/generate.py
uv run python examples/roi/benchmark.py
```

Synthetic fixtures are original MIT material; no third-party figures. Base layouts
are partitioned in `generate.py` before evaluation; all transformations stay with
their base layout. Two development layouts and four reserved regression layouts
cover sequential/diverging/grayscale, tall/wide grids, borders, internal white
lines and large images requiring downsampling. This small split is not an
independent practical benchmark or an M9 automation gate.

| Attempts | Top-3 recall within 0.1 true cell pitch | Maximum edge error | Outcome |
| --- | --- | --- | --- |
| Clean development (2) | 2/2 | 0 px | Review required |
| Clean reserved layouts (4) | 4/4 | 0 px | Review required |
| Blur, radius 0.8 (6) | 5/6 | 1–3 px | Review required; blurred border fails tolerance |
| JPEG, quality 65 (6) | 0/6 | 5 px on the sole proposal | Five abstentions; large case fails tolerance |
| Negative blank/uniform/noise/gradient (4) | Not applicable | Not applicable | All unresolved, no candidates |
| Multipanel (1) | Both true grids proposed | 0 px | Ambiguous, no selection |

All 23 attempts are retained in `examples/roi/benchmark.json`, including failures.
All six clean best proposals have IoU 1.0. Automatic accepted coverage is 0/23;
automatic correct-acceptance rate is undefined and no negatives are automatically
accepted. This is a deliberate review-only policy, not evidence of useful
validated automation. Count-inference accuracy/coverage and OCR localisation
metrics are inapplicable in M7.

Reviewed extraction of the original 20×20 reference is identical to extraction
with manually supplied bounds and satisfies the existing MAE <2% full-range gate.
The regression suite covers this comparison, transform rounding, determinism,
manual bypass, negatives, multipanel ambiguity, caps, strict hints, review import,
CLI statuses and overwrite protection. OCR-enabled baseline tests still run.

Validation in this environment: 181 tests passed with OCR enabled, plus 18
subtests; Ruff, mypy, build and installed-wheel smoke checks passed. The documented
M7 CLI example and complete v0.2 review/reconstruction example passed.

## Limits

Background-distance proposals assume separable rectangular panels on a reasonably
consistent outer background. Large background-coloured cells, touching annotations,
dendrograms, photographic or categorical panels, partial grids, very fine cells,
strong compression, translucent inputs and uncertain borders may require manual
coordinates. Nonopaque images need manual boxes. Thin neutral gridlines are tested;
thick/nonuniform strokes and arbitrary real layouts are not validated. A scored
proposal cannot identify the intended scientific panel. Independently annotated
real figures and a larger frozen benchmark remain work for M9. Reconstructed
numbers still describe the plotted scale, not exact original measurements.
