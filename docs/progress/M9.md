# M9 — Frozen validation and the v0.3 hand-off decision

v0.3.0 completes M7–M9 as a **review-only** CLI/library release. Automatic ROI
hand-off and automatic row/column count acceptance are disabled. No `--auto-roi`
flag is exposed. The frozen benchmark does not establish the required acceptance
policies or gates, and zero automatic coverage is not evidence of useful automation.

## Frozen corpus and evaluation protocol

`benchmarks/m9/manifest.json` freezes **36 original MIT synthetic raster figures**
in corpus `m9-held-out.1`, with image SHA-256s, base IDs, families, dimensions,
regions, true counts, numeric matrices and supported upright labels. Its digest is
`ba1eef99f82ce25c9c3d674257327adfc616be634e5c330c86b8d58f749e6d9a`.
`manifest.sha256` and input hashes are verified before evaluating any figure.

Four fresh base families cover sequential/right-bar, diverging/top-bar,
grayscale/left-bar and gridlines/bottom-bar layouts. Tall/wide grids, different
margins, neutral gaps, borders and supported opposite label sides are included.
Base IDs and splits were declared before evaluation; clean/blur/JPEG/downscaled
variants remain together. Separate challenges cover uniform and low-contrast
matrices, photographic noise, a continuous gradient, categorical tracks, absent
bars, multiple panels, annotations/dendrograms, complete/omitted gridlines and
merged neighbouring colours. The code refuses to overwrite a frozen manifest.
Historical M7/M8 fixtures remain regression data, not new held-out evidence.

The detector's **M8 heuristic values are unchanged**. M9 moves those values into
an immutable, named threshold snapshot, saved alongside detector options/version.
No thresholds were tuned against this corpus. Detector algorithm version remains
`m8.1`; release policy version is `m9-review-only.1`.

All attempted figures, negatives, abstentions and errors remain in
`benchmarks/m9/report.json`. Evaluation separates:

1. Whole-image heatmap/bar proposals with true *supplied* counts; no fixed ROIs.
2. Independent per-axis count proposals conditional on manually annotated heatmap
   bounds. This is not a joint ROI/count acceptance experiment.
3. OCR localisation/strings conditional on a reviewed heatmap and true counts.
4. Numerical extraction from top-three regions satisfying annotated tolerances,
   compared with the same figure using manual bounds and true counts. This is an
   **oracle-assisted review comparison**, never automatic selection by ground truth.

Per-region results include IoU, all four edge errors in pixels and fractions of
**true** cell pitch, top-one/top-three outcomes and association availability.
Count records include candidate recall, coverage/abstention, exact first-ranked
counts, off-by-one/integer-multiple errors and unresolved harmonics. OCR records
retain per-slot expected/raw/final text, confidence, status and geometry association;
text accuracy is separate from region/slot geometry. Numerical comparisons report
finite overlap, MAE/max error, flagged fraction and missing/ambiguous fraction.

## Actual results and failed gates

Local report environment: Python 3.12.14, Tesseract 5.5.0, pytesseract 0.3.13 and
English language data. The report records the actual numerical/image-library
versions. OCR outcomes may vary with engines/language data; the corpus is frozen,
not the external engine's behaviour.

| Measurement | Observed result |
| --- | --- |
| All attempted figures | 36; 0 evaluation errors |
| Whole-image ROI attempts | 32: 27 non-negative, 5 negative; 4 count-only inputs evaluated separately |
| Heatmap top-three recall at <=0.1 true cell pitch per edge | 24/27 |
| Usable bar top-three recall at <=1 px per edge | 18/26 bar-present attempts |
| Complete region pair offered within tolerances | 18/27; requires human target/coordinate review |
| Missing heatmap or bar proposal | 14/32 ROI attempts |
| Negative figures offering a heatmap proposal | 0/5 on this finite set |
| Reviewed numerical comparisons | 18; maximum MAE against manual extraction 0.0 |
| Worst MAE against the synthetic plotted values | 0.00637 of numeric range 1 (below the 2% reference criterion) |
| Conditional row-count candidate recall / coverage | 28/31; 3 abstentions |
| Conditional column-count candidate recall / coverage | 24/31; 7 abstentions |
| First-ranked exact counts | Rows 28/31, columns 24/31; these are proposals, not accepted counts |
| First-ranked off-by-one / integer-multiple errors | 0/28 covered row cases, 0/24 covered column cases in this corpus |
| Conditional label regions within padded-glyph tolerance | 7/8 axes across 4 figures |
| Exact OCR strings | 24/56; 8 unresolved slots |
| OCR false acceptance | 24 wrong strings among 48 accepted (50%); all raw evidence retained |

For example, `S_02` became `S 02` with confidence 88. The string can be assigned to
the correct slot while its punctuation is wrong. This is why localisation,
association and OCR accuracy cannot be combined into a single confidence score.
Even the successful clean numerical cases do not verify biological identifiers.
Every accepted OCR string still requires visual human verification.

The count ranking happens to be exact whenever proposals were offered in this
fresh corpus, but competing harmonics remain. The historical M8 merged-colour
fixture ranks half the true count first, so those recorded failures remain useful
counterexamples. Neither finite ranking result establishes automatic exact counts.
There is no validated independent-support/completeness acceptance classifier.

The gate report records:

- Automatically accepted complete layouts: **0**, from **0 families**, against a
  minimum of 10 accepted layouts across 3 families.
- Automatically accepted exact-count examples: **0 rows / 0 columns**, against
  10 per enabled axis across 3 families, with at least two validated independent
  signals, exact pitch/phase and completeness/harmonic checks.
- Automatic ROI/count coverage: **0%**. Automatic abstention is **100%** by policy.
  Correct-acceptance/exact-count accuracy is **undefined**, not 100%.
- Automatic false acceptance on negatives: **0**, by the review-only policy.

Both acceptance gates are **not established**. A reviewed/oracle-selected case
cannot be counted as automatic acceptance. Saved evidence and benchmark JSON are
not runtime authority to enable automation; extraction provenance records the
current enforced policy independently of saved evidence.

## Supported workflows and manual overrides

Use `detect` to inspect numbered alternatives, then edit an ordinary extraction
config or explicitly select IDs against the saved JSON. Every proposed layout and
inferred count remains review-only; `detect` exits **5** with diagnostics. Invalid
inputs/reviews exit **2**; unresolved OCR extraction exits **4** with review
artefacts and no new matrix/quality files. Existing overwrite/input protection
continues to apply.

A complete v0.3 example, including a blocked uniform case:

```bash
uv run python benchmarks/m9/workflow.py --out work/m9-example
```

The individual positive commands are:

```bash
uv run heatmap-decoder detect benchmarks/m9/figures/grayscale_left-2-clean.png --config benchmarks/m9/review_hints.json --out work/m9-roi
# Expected exit 5. Inspect the overlay before using the fixed fixture review.
uv run heatmap-decoder extract benchmarks/m9/figures/grayscale_left-2-clean.png --config work/m9-roi/config_proposed.json --roi-review work/m9-roi/roi_candidates.json --roi-selections benchmarks/m9/review_selections.json --out work/m9-results
```

Manual pixel boxes retain `[left, top, right, bottom]`, right/bottom exclusive,
in original pixels. Set `requested: []` with a fixed heatmap, or request only the
unfixed region kinds. Fixed regions/counts are authoritative and never silently
adjusted. To correct a supplied count, edit an ordinary manual config or create
new consistent detection hints; an imported saved review cannot silently override
its supplied count. Label-only requests do not require a bar.

Counts may be supplied from visible labels/grid boundaries or explicitly reviewed
from count proposals. Confirm *both* dimensions, outer-grid completeness and
fundamental/harmonic alternatives against the raster. In this release an inferred
count can be used **only after explicit review**; no automatically accepted count
exists. Uniform axes, hidden transitions, repeated neighbouring colours, partial
crops, missing labels and insufficient independent evidence need manually supplied
counts. Never equate the number of recognised labels with the matrix dimension.

Endpoints always remain manual: palette colour cannot identify numeric limits,
scale direction, units or pre-transformation quantities. Bar orientation establishes
physical top/bottom or left/right only. The input must use a continuous linear
scale; categorical/nonlinear/log scales are unsupported. Numerical reconstruction
remains approximate and per-cell colour distance is not a numerical uncertainty
interval. No exact recovery of original biological measurements is claimed.

## Reproduce, provenance and practical limits

```bash
uv run --extra ocr python benchmarks/m9/evaluate.py --ocr --out work/m9-benchmark.json
# Omit --ocr for an engine-free run; omitted OCR is recorded, not reported as success.
uv run --extra ocr python examples/labels/workflow.py --out work/m9-v02
uv run --extra ocr python examples/roi_m8/workflow.py --out work/m9-m8
uv run pytest
uv run ruff check .
uv run mypy src
```

Detection JSON stores immutable heuristic thresholds, detector options/version,
image identity, transform evidence and the release policy. Reviewed extraction
retains that snapshot, config/selection/ROI hashes and the enforced runtime policy.
Legacy M7/M8 saved results remain readable; their absent threshold snapshots stay
absent rather than being attributed to a new detector run. Numeric/manual-only and
v0.2 label/review paths retain their existing behaviour.

The benchmark contains **no independently annotated published real figures**.
It establishes synthetic regression behaviour and exposes failure cases, not
practical coverage on arbitrary scientific figures or a population error rate.
An independently sourced/licensed/annotated real-figure set remains a requirement
before such a claim. We did not replace it with generated plots and call them real
published evidence. Review-only shipping is the specification's fallback when the
M9 gates cannot be established.

Touching annotations/dendrograms, multiple intended panels/shared bars, compressed
or blurred bars, very small cells, low contrast, nonopaque images and unknown text
orientation may need manual bounds. Vertical/angled/multiline labels, perspective
correction, PDFs, tick-value OCR, biological alias inference and a GUI remain out
of scope. A future acceptance policy needs a new untouched evaluation corpus;
editing this report or raising score thresholds cannot enable the current release.

Validation in this environment: 229 OCR-enabled tests passed, plus 18 subtests;
Ruff and mypy passed. The M9 reviewed/blocked example, v0.2 workflow and M8
reviewed example passed. Both v0.3.0 distributions built, and the installed wheel
passed numeric/file-label/detection/review smoke checks outside the source tree
without the OCR extra. Cross-platform CI and the OCR benchmark job run on push.
