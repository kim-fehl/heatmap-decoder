# M15 bounded orientation proposals and publication workflow preparation

## Delivered scope

The Windows frozen-manifest CI failure is fixed and pushed in `0eee909`.
`.gitattributes` preserves LF text checkout bytes and the recorded bytes of CSV
outputs. A new checkout with `core.autocrlf=true` verifies all M9 manifest/image
hashes; all 11 M9 tests pass. Frozen hashes are not normalised or weakened.

M15's bounded orientation implementation, synthetic evidence, reviewed example
and publication-trial runner are delivered. The user will add real-world figures
to the repository manually; publication-image trials are explicitly deferred,
with **zero real-image trials** and no publication generalisation claim.

## Runtime

The opt-in `propose_column_rotations` setting searches above/below a grid at
0/±90°, using the existing exact transform, upright grouping and original-x
assignment path. Shared pixel/call/time limits retain skipped trials. Each trial
keeps raw/original tokens, unassigned geometry, per-slot results, angle, region,
engine metadata, resource cost and reasons. Explicit angle/region sources remain
authoritative. Reviewed candidates carry their angle into extraction.

Only a unique adequate and completed layout hypothesis can support orientation.
Opposite-angle or side contradictions remain separate review alternatives, even
when their boxes coincide; OCR confidence cannot choose between them. Count
signals come from original-coordinate unassigned candidate centres, before slot
fitting, and link the orientation trial. Text remains one observation family;
missing strings are never simply counted as a new dimension.

The detector is `column-orientation.1`, acceptance policy `review-acceptance.4`.
The numeric matching thresholds and experimental export guard are unchanged.
Numeric-only workflows do not depend on identifier/orientation success. Requested
names cannot become generated positional IDs silently. Identifiers, inferred
counts and OCR scales remain outside automatic export scope.

## Frozen synthetic evidence

Each partition contains 24 new base figures, 72 ordinary clean/JPEG85/blur0.65
attempts and eight challenges. Angles 0/±90°, above/below placement, two fonts and
two actual observed palettes are represented. QA checks text patch/slot bounds
and matrix separation before recognition; all ordinary fixtures pass. Numeric
seeds differ; fonts, strings and layouts are shared, and derivatives are
correlated. This is synthetic evidence with limited distribution diversity.

The initial preregistration is retained. Before validation freeze, the nonlinear
challenge was corrected and the capability sampling plan documented. Numeric,
explicit-angle labels and orientation trials run on all derivatives; OCR scales,
composed identifiers and unassigned-text counts run on clean bases and challenges.

For each angle, ordinary explicit OCR is exact on all 192 strings per partition.
Orientation is unique on 24/24 upright attempts and 12/24 for each quarter-turn
sign. The remaining rotated trials retain competing upside-down interpretations.
Even exact heuristic text on this narrow corpus does not verify real identifiers.

Every ordinary manual numeric extraction is fully finite. Worst validation MAE /
maximum errors as fractions of scale range are viridis 0.004122 / 0.016378 and
teal-black-red 0.003902 / 0.013986. The 24 automatically complete validation
matrices are all clean cases, with worst MAE 0.002452 and maximum 0.006722. No
wrong complete ordinary numeric decisions are observed. JPEG/blur whole-figure
failures stay in the denominator; these wider publication-style layouts reveal
further geometry coverage limits, despite accurate conditional extraction.

Diagonal/unlabelled text yields no supported orientation; conflicting sides
retain alternatives; missing slots persist. Underscore names remain a challenge.
Multiple-panel/shared-bar full-figure requests abstain. All challenge identifier
workflows abstain, and all inferred-count/OCR-scale workflows retain zero exports.
Label challenges can still export correct numeric-only values when numbers do not
require the labels. This separation is intentional.

**A supplied linear scale is an assumption that must be verified.** The deliberately
nonlinear challenge, when forced through user-supplied linear endpoints, exports
an unflagged but wrong numeric matrix: validation MAE 16.38%, maximum 25.33% of
range. This is an existing limit of endpoint-only calibration, not evidence that
nonlinear scales are supported. Colour distance cannot verify a numeric scale
model. The OCR-scale/identifier paths do not export these figures. The local
publication runner explicitly leaves non-linear/unverifiable annotations
review-required rather than creating a forced linear reference. Do not report
zero negative numeric exports across this deliberately misconfigured challenge.

## Reviewed workflow and practical limits

The shipped synthetic example selects +90° from the retained angle hypotheses,
then reviews each name by original column index. It writes a 6×8 matrix with 48
finite/unflagged values, bit-identical to numeric-only extraction. The previous
M14 examples retain auto ROI + supplied scale viridis and verified teal–black–red
workflows. These are practical reviewed examples, not real-publication trials.

`publication_trials.py` can evaluate locally added figures using source/licence,
image hash, ROI/count/scale annotations and a recorded second-pass audit. It
passes full images to selective automation, reports explicit manual workflow
agreement separately, and never calls that agreement biological numeric truth.
The candidate retrieval manifest contains source licence checks but no invented
image dimensions, annotations or successful image results. Each real source must
still have panel-specific reuse conditions and annotation history checked.
