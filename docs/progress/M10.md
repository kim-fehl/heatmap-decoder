# M10 — Measured acceptance decisions and ordinary-image robustness

M10 is implemented as development/review functionality. It does **not** release
automatic matrix export, inferred counts or identifier acceptance. M11 tick OCR
and M12 release evaluation are not implemented. Package release version remains
v0.3.0; these changes are recorded under Unreleased.

## Runtime decisions

`acceptance.py` defines typed boundary, phase, grid and bar evidence, and returns
validated `AcceptanceDecision` / `AcceptanceReport` models. Decisions are
`accepted`, `review_required` or `unresolved`, with reason codes and measured
observations. They cover each ROI, heatmap–bar association, count axis, scale,
numeric matching quality and requested identifier verification, followed by a
request-specific overall decision. A rank or OCR confidence cannot pass a check.

Policy `m10-development.1` and detector `m10.1` are versioned independently of
legacy M8 threshold snapshots. Supplied-count checks use original pixels:

- Minimum six-pixel cell pitch, equal-grid consistency and piecewise constancy.
- All four outer edges must close against separable background/border evidence;
  internal transitions must fit the supplied grid phase.
- Bounds must remain within 0.1 cell pitch under foreground thresholds at
  0.85, 1.0 and 1.15 of the configured threshold. Bar stability allows one pixel.
  Stability supports the other observations; it does not verify target identity.
- Near-identical boxes are deduplicated for competition checks, preserving the
  original proposals and coordinates. Different panels/bars require review.
  Candidate and association caps cannot hide competition to manufacture a pass.
- A unique association needs at least 90% observed palette coverage. Bar physical
  orientation and side are independent; both orientations can occur on any side.
- A concrete validated `ExtractionConfig` feeds the existing numerical extractor.
  At most 1% flagged cells and **no missing/ambiguous cells** pass development
  numeric QC. Existing manual extraction/QC defaults are unchanged.

Manual bounds/counts/endpoints remain authoritative and bypass automatic geometry
acceptance. Their numeric QC is still measurable. There is no endpoint recognition
or numerical-scale inference. Observed bar closure is evidence of visible extent,
not proof that a silently cropped palette represents its original full scale;
manual endpoints remain an assumption the user must verify.

Each schema 3 detection JSON preserves the image hash, hints, threshold/policy
snapshots, raw proposals, associations, decisions and review requirements. Schema
1/2 evidence stays readable, with unknown observation provenance by default.
Imported scores, decisions and user-edited policy fields never enable runtime
export. Explicit coordinate/count review still produces an ordinary extraction
config through existing image/ID validation and overwrite protections.

## Bar robustness and bounded staging

Development inspection found ordinary blur/JPEG halos included in the coarse bar
box. For instance, the historical sequential JPEG candidate had transverse error
37.65 RGB units, while its central strip remained smooth. Refinement now compares
peripheral columns to the central, unsmoothed profile and locates end closure.
Noise measured in the central transverse strip supports a bounded step tolerance;
large interior jumps and long plateaus remain separate categorical/discontinuous
checks. Endpoint disturbances are retained separately. Uncertain extent/bounds
remain review-only even when a useful proposal is now available.

Label localisation stages up to three shortlisted heatmaps internally. It retains
raw, unassigned text positions and the associated heatmap ID before final slot
assignment; assigned label counts are never independent evidence. OCR has a shared
per-crop pixel cap (default four million upscaled pixels) and a shared
16-million-pixel job budget, preserving
warnings/losing hypotheses when exhausted. Detection caps images at 16 million
pixels, association attempts at 36, and numeric evaluation at 65,536 cells. Large
or unresolved inputs retain manual extraction as a separate workflow.

Count observations now exclude along-axis stroke pixels and perpendicular
uniform gridline samples from the colour-transition channel. Across a stroke,
colour evidence compares the cell pixels on either side; identical neighbouring
colours do not become transitions just because a black line exists. Each signal
records its observation family and exclusion provenance. Decisions record
alignment, coverage, pitch/phase, distinct support, conflicts and harmonic
alternatives. Repeated OCR remains correlated support. Ranking remains available
for review; inferred counts **never pass** while uniqueness and outer completeness
are unestablished. Supplied counts permit ROI checks even when optional inference
is weak or conflicting. No counts are silently inserted into the proposed config.

OCR label `accepted` retains its historical heuristic meaning. The new independent
`identifier_verification` state is `review_required` for OCR, `user_supplied` for
file labels or `not_requested`. Numeric-only experimental requests explicitly use
positional IDs and reject conflicting identity requests.

## Development results and limitations

[benchmarks/m10/report.json](../../benchmarks/m10/report.json) records **136 ROI attempts**:
96 larger raster variants, eight new challenges and 32 historical M9 ROI inputs.
It also records 20 conditional per-axis count experiments and six optional OCR
runs. Runtime decisions precede truth-based evaluation; no oracle top-three
selection feeds a complete accepted numerical reconstruction.

The 32 larger layouts cover 20×6, 25×8 and 30×10 genes/samples, both label sides,
both sample sides and all eight bar side/orientation combinations. They reuse
three seeded numeric patterns, with dependent clean/blur/JPEG derivatives. All
inputs are original MIT synthetic figures. There are **no independently annotated
published figures or untouched M12 test cases** here. M9 figures, manifest,
evaluator and saved report are unchanged and treated as inspected development
regression data.

| Development subset | Attempts | Correct ROI pair passes | Complete numeric passes | Complete coverage |
| --- | ---: | ---: | ---: | ---: |
| Larger clean layouts | 32 | 32 | 21 | 65.6% |
| Larger blur (0.65 px) | 32 | 0 | 0 | 0% |
| Larger JPEG quality 85 | 32 | 4 | 4 | 12.5% |
| New challenge cases | 8 | 0 | 0 | 0% |
| Historical M9 ROI inputs | 32 | 16 | 13 | 40.6% |

All 96 larger variants offer the true usable bar within one pixel among the top
three proposals. Historical non-negative bar recall improves from 18/26 to
**26/26** on the same inspected inputs. Bar localisation improves without relaxing
full-layout acceptance. Blur and JPEG heatmap bounds often fail outer closure,
phase or refinement stability, causing unnecessary but explicit abstention.
Eleven larger clean sequential cases fail the existing colour ambiguity QC despite
correct geometry. Their retained nearest estimates are not silently published as
complete, reliable values. These are remaining development priorities.

All **38 complete development passes** (25 larger plus 13 historical) have correct
geometry within the stated tolerances. Their worst numeric MAE is **0.5683% of the
true range**, maximum error **1.4325%**, with full finite coverage and no flagged
cells. New challenges include missing/categorical/clipped/partial bars, competing
bars/panels, uniform matrices and wrong supplied counts. No complete challenge
passes were observed; finite zero errors do not prove a population error rate.
Released automatic export coverage is still zero by runtime policy.

Conditional counts use manual boxes, without injecting true counts. The 20 axis
attempts offer the true count and rank it first in 18 cases; two uniform axes
abstain. All 18 covered axes remain review-only. This conditional ranking result
cannot establish joint geometry/count automation or uniquely exclude hidden cells.

On the 30-gene/10-sample OCR references, clean exact suggestions are **30/40** for
left/top and **29/40** for right/bottom, with zero and one unresolved slots.
Blur gives 30/40 and 29/40 exact, with 10 and 11 unresolved slots; JPEG gives 30/40
and 29/40 exact, with zero and one unresolved slots. Raw tokens and each wrong
suggestion remain in the report. In particular, underscores in sample names are
lost even at high confidence. No identifier guessing/correction was added.

Environment: Python 3.12.14, Tesseract 5.5.0 / English data, pytesseract 0.3.13.
Detector/classifier median times are approximately 0.52–0.53 seconds for the
larger layouts, with maximum 0.73 seconds; OCR and file I/O are excluded. Reported
runtime varies by hardware and concurrent load. Defaults/limits and all measured
reason codes are in the saved report. Neither the 70% M12 coverage target nor its
independent base/source/corpus requirements are established.

## Commands and validation

```bash
uv run heatmap-decoder extract examples/m10/figure.png \
  --config examples/m10/config.json --out work/m10-example
uv run heatmap-decoder detect examples/m10/figure.png \
  --config examples/m10/hints.json --out work/m10-review
# Expected exit 5: review decisions and overlay, then use the existing review path.
uv run heatmap-decoder extract examples/m10/figure.png --auto-roi --numeric-only \
  --config examples/m10/hints.json --out work/m10-experimental
# Expected exit 5: diagnostic/review artefacts only; no new matrix/quality outputs.
uv run --extra ocr python benchmarks/m10/evaluate.py --ocr --out work/m10-report.json
HEATMAP_DECODER_OCR_TESTS=1 uv run --extra ocr pytest -q
uv run ruff check .
uv run mypy src
uv build
uv run python tests/smoke_distribution.py
```

Validation includes 293 tests plus 18 subtests with the OCR engine enabled;
Ruff/mypy, bundled numeric examples, large labelled export, M9 review/uniform
workflow, v0.2/M8 review workflows and installed-wheel checks. Staged label review rejects regions associated with a different selected heatmap.
Tests cover all 32
larger clean layouts, ordinary degraded bar regressions, categorical jumps,
partial/clipped bars, conflicting counts, uncertain refinement, candidate caps,
legacy saved schemas, resource limits, preserved existing outputs and explicit
identity-vs-numeric requests. CI retains core platform coverage and adds the M10
development evaluation in its OCR job; historical reports are not overwritten.
