# M11 — Numeric ticks and spatial multi-anchor calibration

M11 adds bounded numeric tick recognition, linear multi-anchor calibration and
explicit scale review. It does **not** enable released automatic scale/ROI/count
export or implement M12. The working checkout retains release version v0.3.0;
these changes are recorded under Unreleased and legend policy
`m11-linear-review.1`. Manual endpoints and existing reviewed workflows remain
supported.

## Recognition and scale contract

`legend.py` finds short dark tick strokes near both text sides of a selected/manual
bar, localises upright text, associates it one-to-one with measured positions and
runs one bounded numeric-line OCR pass per unambiguous stroke. Sparse localisation
can miss an isolated number; a measured stroke permits a bounded line crop. No
fit or desired sign chooses an OCR variant. The adapter's original gene/sample
mode is unchanged (PSM 11); numeric lines use PSM 7.

Measured stroke pixels are masked **only in the OCR copy**, preventing a tick
stroke from becoming a minus sign. Original image pixels remain unchanged for
numeric extraction. Raw engine runs, versions/languages/modes, crop boxes,
original-coordinate boxes, mask rectangles and token membership are retained.
High-confidence cropped text and line/stroke position conflicts still fail.
Ambiguous associations, unparsed plausible text and both-side/duplicate legends
are retained; confidence never chooses the winning scale. Clearly outside-span
captions are recorded as excluded evidence. Text-centre fallback is weaker and
cannot qualify a development scale.

Parser grammar covers signed integers/decimals, Unicode minus, standard `e`
notation and explicit `10^signed_integer`. It records normalization actions and
never guesses minus signs, replaces O/0, reconstructs separated superscripts or
corrects identifiers. Decimal commas require an explicit locale; ambiguous commas,
unrepresentable overflow/underflow and unbounded text are unresolved.

`scale` selects one source:

- Legacy/default `manual_endpoints`: requires start/end values and preserves
  existing endpoint matrices bit-for-bit. An explicit quantity can be recorded.
- `manual_ticks`: requires at least two explicitly supplied/reviewed physical
  positions and values. Contradictory endpoints or OCR/suggested anchors fail.
- `ocr_ticks`: keeps endpoints unresolved and requests inspection. A reviewed TSV
  resolves a concrete manual-tick config for the existing extractor; the original
  request and raw evidence remain in provenance.

Coordinates are original axial pixel indices: y for vertical bars, x for
horizontal. Normalised position is `(position - start)/(exclusive_end-start-1)`.
The first/last sampled pixels are positions 0/1, exactly matching `sampling.py`;
there is no axial inset, only the existing transverse central-half sampling.

Linear fitting uses **all actual spatial positions**, not tick order/equal spacing.
It checks distinct finite positions/values, strict monotonicity, nonzero range,
conditioning <=1000 and bounded value/position residuals. Defaults are 1% of the
anchor value range and two pixels; diagnostic residuals remain visible when a
monotonic nonlinear-labelled scale fails. No outlier is removed automatically.
Two ticks cannot test linearity and need manual confirmation. Three or more are
only development-eligible when every plausible recognised tick passes, stroke
positions agree and endpoint coverage is within two pixels. Interior fits require
explicit review of extrapolation. A shared monotonic OCR mistake can still pass a
line; finite residuals do not establish exact recognition or scientific uncertainty.
Log/piecewise/categorical/nonlinear mapping is not implemented.

## Review, outputs and limits

`legend` works without a heatmap or grid. It writes `legend_ticks.tsv`, an editable
image-bound `legend_review.tsv`, `legend_diagnostic.png` and
`legend_provenance.json`. A full extraction config also works for inspection.
Label-only commands do not probe or require a legend.

The review schema is `index`, `image_sha256`, `include`, `position`, `value`.
Every original index must occur once. Included rows require finite positions
inside the sampled bar and a finite value; a valid linear fit needs at least two
distinct included anchors. Explicit exclusion of unrelated/duplicate proposals
is recorded, not performed by confidence. Missing/duplicate/out-of-range indices,
wrong image hashes, conflicting values and invalid fits fail before matrices.
Raw ticks, unreviewed fit/reasons, reviewed anchors and the review hash remain
separate. OCR-unavailable or resource-truncated evidence requires fixing the
request or supplying manual anchors, not a hidden numeric fallback.

Unreviewed/unresolved OCR extraction exits **6** with review artefacts and no new
matrix/quality outputs. Invalid inputs/reviews exit 2. Existing overwrite and
input-file protection rules apply; review files cannot be overwritten by their
outputs. All OCR scales remain `automatic_export_allowed: false`, including
eligible development fits. Neither saved confidence nor policy/report JSON can
enable a released capability.

Resource limits are explicit: 16-million-pixel images; default 128 px vertical
and 64 px horizontal cross-axis strips with 64 px axial padding; four million
upscaled OCR pixels; at most 16 targeted numeric calls/tick observations; 256
localised text tokens per strip; and a 60-second job deadline. A running OCR call
can overrun that deadline by its existing 30-second timeout. Exceeding limits
stops acceptance and preserves diagnostic reasons. There is no unbounded search.

## Scientific reporting and concise documentation

The README is now 82 lines focused on **biological expression heatmaps**, their
supported layout, recognition workflow and scientific limitations. It includes a
PNG made from actual detector/OCR evidence and a real fit fragment. Coordinate,
label, ROI, threshold and overwrite details moved to
[docs/usage.md](../usage.md); scale-source/review details are in
[docs/legend.md](../legend.md).

Numeric provenance is schema 3 and names the recovered `quantity` (or explicitly
records an unspecified transformation). It does not certify original expression
counts. `quality.csv` adds `value_kind` for estimates, missing/ambiguous values and
endpoint colours that may be lower/upper bounds due to clipping. The matrix keeps
its compatible numeric form; consumers must inspect QC. CSV digits preserve
computation, not measurement precision; colour distance and fit residuals are
not uncertainty intervals.

The reference truly computes per-row mean-centred/population-standardised scores
from seeded synthetic values, then clips them to [-2,2]. Its **25×8** table contains
seven clipped cells. The reviewed export has 193 estimates, five potential lower
bounds and two potential upper bounds, with no flagged/missing cells. Unclipped
scores are retained in synthetic truth to verify the bounds; the decoded table
cannot restore them or the original expression inputs. Gene/sample strings are
explicit UTF-8 files, separate from tick recognition.

## Actual development results

[benchmarks/m11/report.json](../../benchmarks/m11/report.json) contains every one of
**42 conditional synthetic attempts**. Bar bounds are supplied; downstream
comparisons additionally use manual grid bounds/counts. Cases span both
orientations/text sides, 2/3/5/7 ticks, ascending/descending scales, nonuniform
positions, interior ticks, nonlinear/nonmonotone labels, scientific notation,
unparsed text, a misleading title, clipping and blur/JPEG. They reuse one matrix
and derivative layouts, not independent sources. No real published figures,
untouched hold-out or complete end-to-end M12 validation is claimed. M9/M10 saved
reports remain unchanged historical evidence.

| Measurement | Observed result |
| --- | ---: |
| Attempts retained | 42 |
| Plausible tick observations scored | 192 |
| Exact parsed tick values | 176/192 (91.7%) |
| Cases with complete exact tick values | 36/42 |
| Observed sign errors against displayed glyphs | 0/192 |
| Development-eligible scale candidates | 20/42 |
| Wrong tick-value cases among eligible candidates | 0/20 |
| Review-required / unresolved cases | 29 / 13 |
| Released automatic scale acceptances | 0 |

Eight clean two-tick cases remain review-required rather than becoming eligible.
Three/five-tick ordinary cases work across both orientations and text sides.
All eight seven-tick variants remain unresolved: some vertical OCR confidences
fall below the documented default, and dense horizontal text can merge/span
neighbouring tick bands. The scientific-notation case retains unparsed/clipped
text rather than manufacturing a fit. Interior ticks retain a line but require
extrapolation review. Nonlinear, nonmonotone, unparsed and clipped cases stop with
explicit evidence. These are actual failures and future development priorities.

Numerical diagnostics use the **recognised fit**, not manual endpoint substitution
or oracle candidate selection. Among the 20 eligible candidates, maximum MAE is
**0.2342%** of the true displayed range and maximum single-cell error **0.8311%**.
Minimum finite coverage is 99.5% and maximum matching-flag fraction 0.5%; these are
separate numeric QC observations, not evidence that complete M12 automation passes.
No rejected/unreviewed OCR request publishes a matrix.

Environment: Python 3.12.14, Tesseract 5.5.0 with English data and pytesseract 0.3.13.
Median inspection time is about 1.10 seconds, maximum 1.55 seconds on this run;
raw engine metadata is recorded. Fonts/engines/hardware can change outcomes.
Finite zero errors in the eligible subset do not establish a population guarantee.

## Verification and commands

```bash
uv run --extra ocr heatmap-decoder legend examples/m11/figure.png \
  --config examples/m11/legend.json --out work/m11-inspection
# Expected exit 6. Inspect every proposed position/value.
uv run --extra ocr heatmap-decoder extract examples/m11/figure.png \
  --config examples/m11/labelled_config.json \
  --legend-review examples/m11/reviewed_ticks.tsv --out work/m11-reviewed
HEATMAP_DECODER_OCR_TESTS=1 uv run --extra ocr pytest -q
uv run ruff check .
uv run mypy src
uv build
uv run python tests/smoke_distribution.py
```

Verification covers grammar, locale, powers, overflow/underflow, sample-position
conventions, nonuniform 2/3/5/7-anchor fits, directions, residual/conditioning
failures, minus loss, misleading/ambiguous text, clipping, resource deadlines/caps,
review identity/indices/source conflicts, optional OCR, legacy numerical identity,
actual 25×8 reconstruction and endpoint-bound QC. Existing v0.2/M8/M9 workflows
and labelled matrix/quality alignment regress cleanly. CI runs the M11 OCR report
and reviewed example alongside existing checks and builds; installed-wheel tests
exercise the manual anchor API with OCR absent.
